# Экономный режим

## Принцип

Лимит жгут не отдельные операции, а **число раундтрипов × размер контекста главной сессии**. Каждый тулколл в разросшейся сессии (~200k) оплачивается как перечитывание всей истории: 174 вызова цикла «клик → кадр → проверка» = 73% пятичасового лимита. Тот же цикл в сабагенте живёт в собственном контексте 5–20k и возвращает наружу отчёт в 10 строк.

## Лестница моделей

| Кто | Что делает |
|---|---|
| Fable / главная сессия | только анализ, решения, синтез; циклы не водит |
| Opus-сабагент | сложные автономные подзадачи: отладить подсистему, ревью |
| Sonnet-сабагент | механика с суждением: вождение стендов, серии грепов, черновики доков |
| Haiku-сабагент | чистая механика: массовые переименования, сбор списков |
| gemma4:26b (ollama, скрипт) | текстовая разметка без тулов — правила ниже |

**Интерактивные циклы (стенды, поллинг) — ВСЕГДА в сабагенте**: `Agent(model: "sonnet")`, в промпте — конкретная задача, критерий успеха, инструменты стенда, стоп-правило; наружу — отчёт ≤10 строк + пути ключевых файлов.

**Главная сессия на Opus** (активный чат, не агент): перед планированием и перед ревью спросить пользователя, не задействовать ли Fable — переключением сессии или Fable-агентом под эту подзадачу. Это единственные два места, где эскалация вверх по лестнице оправдана; механику это не касается — она всё равно уходит вниз.

**Делегирование — только вниз по лестнице**. Fable- и Opus-агенты остаются диспетчерами даже будучи агентами: Opus-агент, ведущий автономную подзадачу (отладка подсистемы, ревью), сам запускает Sonnet/Haiku-агентов под свою механику — это и есть смысл его автономности. Sonnet- и Haiku-агенты — листья дерева: исполнители, своих агентов НЕ запускают (механика, порученная механику, жжёт лимит бесконтрольно, а отчёты искажаются при пересказе через звенья). Строку «своих сабагентов не запускай, работай сам» включать явно в каждый промпт Sonnet/Haiku-агента; в промпт Opus-агента вместо неё — «механику дели на Sonnet/Haiku-сабагентов, сам держи только диагноз и решения».

## Распределение по фазам

Задача режется на четыре фазы; у каждой свой дорогой ресурс.

| Фаза | Кому | Почему так по деньгам |
|---|---|---|
| Разведка: грепы, чтение файлов, дампы, карты | Haiku/Sonnet веером | дорог объём: сырьё в 10–100× толще выводов из него, а качество дёшево — факт либо найден, либо нет, сверяется грепом |
| Анализ и решение: гипотезы, диагноз, архитектура | главная сессия | дорого качество: ошибка решения переоплачивается всеми фазами ниже; на вход — выжимки, не сырьё |
| Исполнение: правки, прогоны, стенды | Sonnet (с суждением) / Haiku (механика) | дорог объём раундтрипов; решение уже принято, суждение только локальное |
| Верификация | исполнитель или отдельный Haiku | проверка по готовому критерию — механика; сам критерий формулирует главная сессия ДО исполнения |

**Вниз уходит объём, наверху остаётся выбор.** В контексте главной сессии не должно
оказаться ни одного токена, который не влияет на решение.

## Отчёт агента попадает в дорогой контекст целиком

Каждая строка отчёта живёт в главной сессии до конца работы и переоплачивается
каждым следующим тулколлом: отчёт в 200 строк при 50 последующих вызовах ≈ 10k
строк переплаты.

Возвращать: вердикт по каждому вопросу промпта (строка: да/нет/значение); факты
как `путь:строка — что там` (не содержимое); числа уже посчитанными (`grep -c`,
`wc`); явное «не найдено»/«не уверен» вместо молчания.

Никогда: содержимое файлов, листинги, дампы, JSON, пересказ кадров, ход поиска.
Всё толще 20 строк — в файл, в отчёте путь + 3 строки сути; главная сессия грепает
файл точечно. Лимит отчёта (разведка ≤20 строк, стенды ≤10) писать в промпт явно —
без лимита агент возвращает всё, что нашёл.

## Когда делегировать невыгодно

Запуск агента стоит главной сессии ~2 раундтрипа на полном контексте (спавн +
чтение отчёта), плюс агент заново открывает файлы, которые главная уже читала.

Порог: делегировать при **≥3 ожидаемых тулколлах** ИЛИ когда появится хоть один
вывод/кадр, ненужный после получения ответа. 1–2 вызова с известными путями —
делать самому, экономия нулевая.

Не делегировать также, когда пересказ контекста в промпт вышел бы длиннее экономии
(>40 строк ради 3–4 вызовов); когда нет проверяемого критерия успеха — сначала
сформулировать критерий; когда суждение неотделимо от решения (выбор гипотезы по
ходу чтения кода) — это фаза анализа, вниз она не уходит.

## Композиция

- **Веер, а не цепочка**: независимые вопросы — параллельные `Agent`-вызовы в одном
  ответе. Цепочка — только если без вердикта А агент Б бессмыслен; пересказ искажает
  факты на каждом звене, глубже 2 звеньев не строить.
- Бюджет веера: N агентов × лимит отчёта ≤ ~100 строк в главный контекст суммарно.
  Вопросов больше — укрупнять агентов, а не отчёты.
- **Факты — в файл**: разведчики пишут находки в общий файл (`путь:строка — факт`),
  в отчётах остаются вердикты.
- **Скрипт вместо агента**: шаг без ветвления по смыслу (convert, diff, прогон,
  подсчёт) — это Bash. ≥3 одинаковых шага по списку — цикл в скрипте, не 3 агента;
  агенту достаются только упавшие элементы.
- **Оркестровка**: известную заранее последовательность (собрать → прогнать →
  сравнить → сводка) оформлять скриптом один раз. Инструмент `Workflow` берёт это на
  себя детерминированно, но запускается ТОЛЬКО по явной просьбе пользователя —
  сам его не предлагать без запроса.

## Промпт агенту: платишь один раз или дважды

Переделка = полная цена агента × 2 + разбор причин на полном контексте главной.
Обязательные части промпта (пропуск любой — главный источник переделок):

1. Рабочая папка и конкретные пути; агент не знает историю сессии — никаких «как обсуждали».
2. Задача одним абзацем: сделать X, НЕ делать Y — границы явно.
3. Критерий успеха, проверяемый без главной сессии (маркер в логе, exit code, число).
4. Команды дословно, готовыми строками — не «найди скрипт».
5. Формат отчёта: лимит строк, вердикт первой строкой, факты как `путь:строка`.
6. Стоп-правило и строка про сабагентов — см. соответствующие разделы выше.

## Скриншоты

- Первичная сверка — **маркеры в логе** (grep), не глазами.
- Кадр смотреть только при провале проверки.
- Перед Read уменьшать: `convert кадр.png -resize 640x360 кадр-s.png` (или `import -resize`).
- Кадры копятся в контексте навсегда — сериям кадров место в сабагенте.

## Большие выводы и батчинг

- JSON-карты, дизасм, длинные листинги → **в файл**; в чат только grep-сводку / wc.
- Независимые команды — одним Bash-вызовом (`&&` / `;`) или параллельными тулколлами в одном ответе.

## Стоп-правило

Две итерации интерактивной задачи без прогресса → **остановиться**, вернуть диагноз и переформулировать подход. Не долбить: 15 кадров боя впустую — реальный случай.

## Локальная gemma4:26b — текстовая механика

Только через скрипт (ollama API), не как агент — тулов у неё нет. `num_ctx=32768` обязательно.

- **Годится**: построчная разметка/классификация (проверено 60/60 при think=false за 17 с); качественная выжимка логов.
- **НИКОГДА**: точные подсчёты (насчитала 234 из 577) — это grep/python.
- Длинные имена из её ответа сверять вхождением в исходник (1/60 исказила).
- **think**: батчи — СТРОГО `think=false` (с think=true батч из 60 строк утонул: 329 с, 102k знаков рассуждений, ответ пустой — упёрся в num_ctx); `think=true` — только один сложный элемент на вызов.
- Шаблон: скрипт режет данные → gemma4 размечает → python сверяет и считает.
- Вызов: `curl -s localhost:11434/api/generate -d '{"model":"gemma4:26b","prompt":"…","think":false,"stream":false,"options":{"num_ctx":32768}}' | jq -r .response`

## Переделки дороги

Скриптованный маршрут по игре сначала прогонять с покадровой сверкой (сабагентом), и только потом жать полный прогон.

## Красные флаги

| Мысль | Реальность |
|---|---|
| «Быстренько погрепаю сам» в разросшейся сессии | 5 грепов × 200k контекста за то, что агент вернул бы десятью строками |
| «Изучи и расскажи всё про X» разведчику | без вопросов-вердиктов вернёт 200 строк пересказа в дорогой контекст |
| «Анализ отдам Haiku, он дешёвый» | неверное решение переоплачивается всеми фазами ниже |
| «Один кадр быстрее глянуть самому» | 67 кадров «по одному» = 15% лимита |
| «Сабагенту стенд не объяснить» | шаблон промпта уже написан — см. проектные доки |
| «Ещё одна итерация — и получится» | два холостых прохода = стоп; 15 кадров боя впустую |
| «Скрипт простой, жму полный прогон» | переделка дороже покадровой сверки |
| «Выведу в чат, потом посмотрю» | вывод живёт в контексте до конца сессии |
