# GREEN: проверка сценариями-соблазнами (2026-08-23)

Два Haiku-сабагента получили текст скилла и сценарии, провоцирующие базлайновые
провалы. Проверялось: примет ли дешёвая модель по одному лишь тексту скилла
правильные решения.

## Сценарий 1: вождение стенда

«Главная сессия с контекстом ~150k, надо проверить фикс движка: запустить стенд,
дойти до боя, проверить. Много кликов и кадров.»

Результат — ПРОЙДЕН: агент делегировал вождение Sonnet-сабагенту по шаблону из
проектной доки, первичную сверку назначил по grep в логе, стоп-правило воспроизвёл.

Вскрытая дыра: агент собрался скриптовать сам бой — ровно та ловушка, где в
базлайне сгорели 15 кадров. Закрыто: в проектную доку стендов добавлен явный
запрет «бой скриптом не берётся, сабагент доводит только ДО боя».

## Сценарий 2: подсчёт и классификация лога

«Лог на 577 строк: посчитать строки с маркером и классифицировать ошибки по типам;
локально есть ollama с gemma4:26b.»

Результат — ПРОЙДЕН: подсчёт — grep (не gemma), классификация — gemma4 батчами
с think=false и num_ctx=32768, сверка и итоговые числа — python.

Вскрытая дыра: агенту не хватило готового вызова ollama API. Закрыто: в скилл
добавлена curl-строка с нужными параметрами.

## Ограничения проверки

По одному прогону на сценарий (сам скилл запрещает жечь токены на избыточные
реплики); задача-специфичные пробелы из отчётов агентов (маркер HP в логе,
координаты кликов) — не дыры скилла, их заполняет диспетчер под конкретную задачу.
